TL;DR — Sparse attention must do something with the 99% of the KV cache it does not read. Discarding that tail biases the output and sampling it fails at low reads. OpenAttention folds every unread token into a few count-aware cluster proxies and lets an ErrorGate spend the exact-read budget where the estimated error is largest. The result: 99% of dense accuracy at a 1% read on RULER-32K HARD (86.30 vs 87.04, best baseline 48.22), state-of-the-art across models and context lengths, and a fused decode kernel that runs the attention stage 10× faster than dense attention.

Method in one minute

The problem: what happens to the unread tail?

Two findings drive the design. First, the simplest possible proxy — one token folding the entire tail into its count-aware mean — already yields lower output error than a sample at every read behind a practical selector. Second, in closed form, at low reads sampling nearly doubles the weight error of discarding while a single proxy stays below it.

The pipeline

  1. QGC — Query-Geometry Clustering. Keys are clustered once per prefill in a rank-16 projection aligned with the directions queries actually probe (the top eigenvectors of M = ½Mst + ½Mq). Training-free; the static metric Mst is measured once on 18 held-out requests.
  2. QGS — Query-Geometry Selector. Each step scans rank-32 int8 key codes in the same geometry and takes the top-k. No learned hash functions, no per-model training.
  3. ErrorGate. Each cluster caches count, mean and diagonal-variance statistics. ErrorGate estimates each cluster's softmax-weight error and allocates the exact-read budget by water-filling — unlike prior methods that rank clusters by centroid score alone.
  4. Count-aware proxies. Every token still unread joins its cluster's proxy with logit z̄b + log nb and the mean value, keeping the softmax mass-preserving.
  5. OpenAttention.flash. A fused Triton kernel computes selected tokens, expanded tokens and proxies in one online-softmax pass.
